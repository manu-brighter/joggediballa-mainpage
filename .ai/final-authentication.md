## Overview

The app uses Google OAuth 2.0 as its primary authentication mechanism. After a successful OAuth flow, a signed JWT is stored in an HTTP-only cookie. Every tRPC request re-verifies the JWT and looks up the full user from the DB. Authorization is handled by two coexisting systems: static role procedures and dynamic permission checks backed by MySQL.

## Google OAuth Flow

**Files:** `server/_core/googleAuth.ts`, `server/_core/googleAuthRoutes.ts`

### How It Works

1. `GET /api/auth/google` → Passport redirects browser to Google consent screen (`profile` + `email` scopes)
2. Google redirects back to `GET /api/auth/callback/google?code=...`
3. Passport exchanges code for profile via Google API
4. Strategy callback: `getUserByOpenId(googleId)` to detect new vs. returning user
5. New users get role `visitor`; exception: if email matches `ADMIN_EMAIL` env var (case-insensitive), role `admin`
6. Existing users' roles are never changed on re-login (`role` omitted from upsert)
7. `upsertUser()` in DB, `createActivityLog('login' | 'registration')`
8. If new visitor: async email notification to `CONTACT_EMAIL_TO` (non-blocking)
9. JWT created (HS256, 7d), set in HTTP-only cookie, user redirected to `/`
10. Subsequent requests: JWT verified by `sdk.verifySession()`, user fetched from DB

### Known Issues

| Issue | Severity | Location |
|---|---|---|
| `/login-failed` redirect goes to 404 | Medium | `googleAuthRoutes.ts:57, 66, 101` |
| `req.get("host")` used unsanitized for redirect URL | Low | `googleAuthRoutes.ts:90` |
| express-session mounted but unused | Negligible | `googleAuthRoutes.ts:22-33` |
| Scope duplicated (in Strategy + in route handler) | Negligible | `googleAuth.ts:44`, `googleAuthRoutes.ts:45` |

## JWT & Session Cookies

**Files:** `server/_core/sdk.ts`, `server/_core/googleAuthRoutes.ts`, `server/_core/cookies.ts`, `server/_core/context.ts`

### How It Works

**Signing** (`googleAuthRoutes.ts:70-80`):
```
SignJWT({ openId, appId: "google-oauth", name, email, role })
  .setProtectedHeader({ alg: "HS256", typ: "JWT" })
  .setExpirationTime("7d")
  .sign(TextEncoder().encode(JWT_SECRET || 'fallback-secret-change-in-production'))
```

**Verification** (`sdk.ts:200-233`):
```
jwtVerify(cookieValue, ENV.cookieSecret, { algorithms: ['HS256'] })
// Requires isNonEmptyString for openId, appId, name — all three
```

**Per-request flow** (`sdk.ts:259-301`):
1. Parse `Cookie` header → extract `manus-session`
2. `verifySession()` → validate signature + expiry
3. `getUserByOpenId(session.openId)` → fetch full User from DB
4. If user not in DB: attempt Manus OAuth sync (fails for Google users) → `ForbiddenError`
5. `upsertUser({ lastSignedIn })` — **write on every authenticated request**
6. Return User → `ctx.user`

**Cookie options** (`cookies.ts:43-48`):
- `httpOnly: true`, `path: "/"`, `sameSite: "lax"`, `secure: isSecureRequest(req)`
- `secure` dynamically determined via `x-forwarded-proto` (Nginx-compatible)
- No `domain` set — exact hostname only

### Known Issues

| Issue | Severity | Location |
|---|---|---|
| JWT_SECRET mismatch: signing uses `'fallback-...'`, verification uses `''` if unset — Google OAuth completely non-functional without JWT_SECRET | **High** | `googleAuthRoutes.ts:9`, `env.ts:3` |
| Empty `name` field → JWT verification fails (Google user with no display name) | Low | `googleAuthRoutes.ts:73`, `sdk.ts:216-219` |
| `upsertUser(lastSignedIn)` write on every authenticated request (hot write path) | Low | `sdk.ts:295-299` |
| Manus OAuth fallback for Google users throws `ForbiddenError` (user deleted from DB) | Low | `sdk.ts:276-288` |
| No token revocation — stolen tokens valid for 7 days | Accepted | Stateless design |

## Role & Permission System

**Files:** `server/permissions.ts`, `server/routers.ts`, `server/db.ts`, `client/src/hooks/usePermissions.ts`

### Role Hierarchy
```
admin > maintainer > editor > user > visitor
```

### Two Coexisting Authorization Systems

**System 1 — Static procedures** (`routers.ts:27-62`):
```typescript
adminProcedure      → role === 'admin'
maintainerProcedure → role in ['admin', 'maintainer']
editorProcedure     → role in ['admin', 'maintainer', 'editor']
```
No DB calls. Always correct regardless of DB state.

**System 2 — Dynamic `requirePermission(key)`** (`routers.ts:65-72`):
```typescript
const requirePermission = (key: string) =>
  protectedProcedure.use(async ({ ctx, next }) => {
    const allowed = await hasPermission(ctx.user.role, key);
    if (!allowed) throw new TRPCError({ code: 'FORBIDDEN' });
    return next({ ctx });
  });
```
Checks `rolePermissions` table via in-memory cache (5-min TTL per role). Result depends on DB state.

### Permission Keys (default intended values)

| Key | Intended roles |
|---|---|
| `edit_events` | admin, maintainer, editor |
| `manage_sponsors` | admin, maintainer |
| `manage_goennermitglieder` | admin, maintainer |
| `edit_shotcounter` | admin, maintainer, editor |
| `reset_shotcounter` | admin |
| `edit_team` | admin, maintainer |

### ⚠️ Critical: Default Permissions Are Never Auto-Seeded

`initializeDefaultPermissions()` in `db.ts:960` is exported but **never called anywhere**. On a fresh deployment with an empty `rolePermissions` table:
- Every `requirePermission()` call returns `false`
- Admin cannot create/edit events, manage sponsors, or touch shotcounter scores — even though they have `admin` role
- Only `adminProcedure`-gated routes (user management, audit log) still work

**Required action on fresh deployment**: Admin must manually seed permissions via the dashboard after first login.

### Permission Cache (`permissions.ts`)

```typescript
const permCache = new Map<string, { keys: string[]; exp: number }>();
// Key: role name. Value: { permission keys[], expiry timestamp }
// TTL: 5 minutes. Invalidated globally by clearPermissionCache().
```

- `visitor` always returns `[]` (no DB call, no cache entry)
- One DB call per role per TTL window (`getAllPermissions()` fetches all rows, filters in-memory)
- Cache is process-memory — multi-instance deployments have per-instance caches

### Frontend

`usePermission(key)` → `trpc.permissions.getMyPermissions.useQuery()` → server-side `getUserPermissions(role)` (uses 5-min server cache).

Client caches for 30s, refetches on every component mount.

## Data Flow Summary

```
Browser click "Login"
  → GET /api/auth/google
  → Google consent
  → GET /api/auth/callback/google?code=...
  → Passport: profile → upsertUser → JWT (HS256, 7d) → Set-Cookie: manus-session=<jwt>
  → Redirect to /

tRPC request with cookie
  → context.ts: sdk.authenticateRequest(req)
  → sdk.ts: parseCookies → verifySession(jwt) → jwtVerify (signature + expiry + fields)
  → db: getUserByOpenId(openId)
  → db: upsertUser({ lastSignedIn: now })
  → ctx.user = User

Protected route (requirePermission)
  → hasPermission(ctx.user.role, key)
  → permCache hit → return cached keys
  → permCache miss → db.getAllPermissions() → filter by role → cache → return
  → keys.includes(key) → true/false → next() or TRPCError FORBIDDEN
```

## Action Items

### High Priority
1. **Set `JWT_SECRET` and add startup assertion** — If not set, Google OAuth is fully broken (signing uses fallback, verification uses empty string). Add a startup check:
   ```typescript
   if (!process.env.JWT_SECRET) throw new Error('JWT_SECRET must be set');
   ```
2. **Call `initializeDefaultPermissions()` at startup** — Add to server startup code so a fresh deployment doesn't leave all content mutations denied for everyone.

### Medium Priority
3. **Add `/login-failed` route** — OAuth failures redirect to a 404. A simple error page with a "Try again" link would improve UX.
4. **Fix redirect URL construction** — Use `GOOGLE_CALLBACK_URL` env var (already available) to derive the redirect base URL instead of `req.get("host")`, which is spoofable.

### Low Priority
5. **Remove unused express-session** — `passport.session()` and the session middleware can be removed since `session: false` is used on all auth routes.
6. **Debounce `lastSignedIn` writes** — `upsertUser({ lastSignedIn })` runs on every authenticated request. Consider updating only if `lastSignedIn` is more than N minutes old.
